# ADR: профиль сборки LLDAP

## Статус
Принято для проверки сборкой.

## Решение
- Собирать исходники LLDAP из официального Git-тега `v0.6.3`.
- Использовать Rust `1.89.0` согласно upstream `rust-toolchain.toml` и `wasm32-unknown-unknown` для Web UI.
- В `02_dep.Dockerfile` устанавливать build-зависимости через `mk-build-deps`, готовить `wasm-pack`, `wasm-bindgen-cli` той же версии, что и crate в `Cargo.lock`, и vendored Rust-зависимости.
- Внешние CSS, JavaScript и шрифты из upstream `app/static/*.txt` получать на этапе зависимостей; в конечном артефакте использовать `index_local.html` без CDN.
- В `03_bin.Dockerfile` собирать сервер, migration tool, set-password и WebAssembly-интерфейс без сетевого доступа, с `--offline --locked` для Cargo и `--mode no-install` для wasm-pack.
- Сжимать WASM через `gzip -n` без сохранения времени и имени исходного файла для воспроизводимости.
- Размещать исполняемый сервер в `/usr/sbin/lldap`, вспомогательные инструменты в `/usr/bin`, web-ресурсы в `/usr/share/lldap/app`.
- Не запускать тесты и не включать документацию, dev-файлы или служебные образы; финальный образ `FROM scratch` содержит только `/target`.
- Сборочный профиль не создаёт systemd-unit и не задаёт секреты или состояние каталога.

## Последствия
- Для запуска Web UI необходимо явно настроить `assets_path = "/usr/share/lldap/app"` или соответствующую переменную `LLDAP_ASSETS_PATH`.
- Секреты LLDAP, ключи шифрования и база данных должны сохраняться в постоянном каталоге при развёртывании сервиса.
- При обновлении версии Rust, wasm-pack или `Cargo.lock` необходимо пересматривать совместимость wasm-bindgen.
- Сборка должна проходить штатной командой `make lldap`, с проверкой совпадения SHA-256 при повторной сборке.
