# ADR: профиль сборки Buildbot

## Статус
Принято для проверки сборкой.

## Контекст
Buildbot 4.3.0 — Python-приложение, включающее основной сервер,
worker и Web UI. Для переноса в `nell` необходимо определить состав
пакетов и runtime-зависимостей.

## Решение
- Использовать официальный тег `v4.3.0` репозитория `buildbot/buildbot`.
- Собирать `master[bundle]`, включая Web UI, worker и входящие в
  bundle компоненты, вместо отдельных Python-дистрибутивов.
- Использовать Python 3.14.7 из существующего образа
  `pkg/dev/python3.14` до появления профиля Python в `nell`.
- Включить команду `/usr/bin/buildbot` и systemd-unit
  `buildbot.service`.
- Использовать glibc 2.44, OpenSSL и zlib из собственных
  `bin`-образов `nell`; `libbz2`, `libgcc_s`, `libsqlite3`,
  `libzstd` брать из сборочного окружения, а `libpthread` — из glibc.
- Для работы с репозиториями поставлять `git` из существующего
  `pkg/utils/git:2.56.0` до появления профиля Git в `nell`.

## Последствия
- Поставляется комплект Buildbot с Web UI и worker, а также
  исполняемой командой и unit для запуска master.
- Для исполнения службы требуется отдельная конфигурация и
  каталог состояния Buildbot.
- Источники Python и Git остаются временными зависимостями от
  `pkg` до выполнения общей задачи по их переносу.
