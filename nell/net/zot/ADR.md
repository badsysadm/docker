# ADR: профиль сборки zot

## Статус
Принято для проверки сборкой.

## Решение
- Получать исходники zot из официального upstream Git-тега выбранной версии.
- Собирать полнофункциональный сервер `zot` с набором штатных расширений, включая встроенный Web UI, и клиент `zli`.
- Подготавливать Go toolchain, Go vendor и готовые статические ресурсы ZUI в `02_dep.Dockerfile`.
- Версию Go выбирать согласно требованиям `go.mod`, а версию ZUI — согласно Makefile соответствующего upstream-релиза.
- Использовать upstream-архив ZUI, не пересобирать frontend из источников.
- На этапе `03_bin.Dockerfile` компилировать без обращения к внешним репозиториям с `-mod=vendor`, `-buildvcs=false`, `-trimpath` и штатными Go build tags.
- Использовать `CGO_ENABLED=0` и `GOEXPERIMENT=jsonv2`, как в upstream-сборке; не линковать динамические сторонние библиотеки.
- Не собирать и не запускать тесты; не собирать документацию и не включать её в конечный образ.
- Устанавливать только исполняемые файлы в `/target/usr/bin` с правами `0755`; финальный образ — `FROM scratch`.

## Последствия
- Функциональные расширения увеличивают время компиляции и число Go-зависимостей.
- Для обновления релиза может потребоваться согласованное изменение Go toolchain и архива ZUI.
- Сборка ZUI не воспроизводится из исходников в данном проекте; используются официальные предварительно собранные ресурсы.
- Воспроизводимость итогового `bin`-образа проверяется штатной командой `make zot`.
