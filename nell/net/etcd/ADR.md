# ADR: профиль сборки etcd

## Статус
Принято для проверки сборкой.

## Решение
- Собирать upstream etcd версии 3.7.3 с официального Git-тега.
- Включить три штатных исполняемых файла: `etcd`, `etcdctl` и `etcdutl`.
- Использовать Go 1.26.10 согласно `go.work` upstream.
- Загружать Go toolchain и разрешать зависимости только на этапе `02_dep.Dockerfile`.
- Подготавливать workspace vendor посредством `go work vendor` в `02_dep.Dockerfile`.
- На этапе `03_bin.Dockerfile` запускать upstream `scripts/build.sh` с `-mod=vendor`, `-buildvcs=false` и без доступа к Go proxy.
- Собирать с `CGO_ENABLED=0` и `-trimpath`; все исполняемые файлы не требуют динамической линковки сторонних библиотек.
- Не собирать и не запускать тесты и не включать документацию в конечный bundle.
- Размещать в `scratch`-образе только исполняемые файлы в `/target/usr/bin`.

## Последствия
- В `dep`-образе должны присутствовать зависимости всех модулей рабочего пространства etcd.
- Для сборки новой версии требуется обновить Go toolchain, если upstream изменит минимальную версию.
- Профиль не предоставляет CGO-зависимых возможностей.
- Воспроизводимость двух последовательных сборок проверяется штатным `make etcd`.
