# ADR: профиль сборки и функциональное пакетирование systemd

## Статус
Принято.

## Контекст
systemd объединяет менеджер служб, системные библиотеки, udev, PAM/NSS,
службы интеграции с ОС и дополнительные инструменты. Для NELL требуется
сохранить функциональные возможности upstream-сборки, но позволить
устанавливать только нужные компоненты без обязательной установки всего
набора системных служб и инструментов.

Полная статическая линковка systemd несовместима с используемыми
динамическими системными интерфейсами, включая PAM и NSS. Особенности
профиля сборки и его исключения из общего контракта NELL должны
сохраняться независимо от способа Debian-пакетирования.

## Решение
- Собирать systemd через Meson/Ninja в режиме release, сохраняя явно
  включённые системные интеграции: PAM, NSS, resolver, audit, SELinux,
  AppArmor, seccomp, cryptsetup, TPM2, networkd, resolved, logind и другие.
- Не требовать полной статической линковки: для системных интерфейсов
  systemd допускаются динамические runtime-зависимости.
- Использовать OpenSSL из собственного профиля NELL вместо Debian
  `libssl-dev`; kmod получать из Debian `libkmod-dev`.
- Сохранять разделяемые библиотеки и собирать статические
  `libsystemd` и `libudev` с PIC; сохранять shared-link режимы
  компонентов, установленные профилем сборки.
- Формировать Debian-пакеты из единого уже собранного OCI bundle
  (`/target`), не пересобирая systemd по отдельности для каждого
  бинарного пакета.
- Разделять результат по функциональному назначению: основной менеджер
  служб, общие и публичные библиотеки, заголовки и статические архивы,
  udev, PAM/NSS, отдельные системные службы, пользовательские утилиты
  и дополнительные интеграции. Файлы конкретной службы, включая её
  конфигурацию и механизмы активации, относить к соответствующему пакету.
- Обязательные для работы ядра компоненты, включая journald, tmpfiles
  и sysusers, оставлять в зависимостях базового `systemd`; остальные
  службы и функции предоставлять отдельными пакетами по необходимости.
- Предоставлять отдельные необязательные `systemd-filesystem`,
  `systemd-kernel`, `systemd-tpm2` и другие специализированные
  пакеты. `systemd-tpm2` содержит TPM2-специфичные инструменты,
  PCRLock/NvPCR-данные, units и cryptsetup TPM2-плагин; базовый
  `systemd` и `systemd-boot` не требуют его установки.
- Разделять контейнерные и виртуализационные возможности по назначению
  (в частности, nspawn, machined, importd, portabled, vmspawn,
  nsresourced и mountfsd), вместо объединения их в один
  `systemd-container`.
- Отделять загрузочные компоненты UEFI и утилиты формирования UKI,
  а также Bash/Zsh completion, чтобы не делать их обязательной частью
  системного менеджера.

## Последствия
- Единый OCI bundle остаётся источником артефактов для всех Debian-пакетов,
  поэтому распределение файлов не меняет набор возможностей скомпилированного
  systemd и не требует отдельных сборочных профилей.
- Минимальная установка может исключать службы, инструменты, поддержку
  контейнеров, TPM2 и интеграции, не нужные конкретной системе.
- Разделение TPM2-файлов по пакетам не удаляет TPM2-код и библиотеки из
  общих бинарных файлов, собранных с включённой поддержкой TPM2.
- Пакеты с общими библиотеками и системными службами требуют согласованных
  зависимостей и корректного владения файлами. Перераспределение файлов
  влияет на совместимость при обновлении ранее установленных пакетов.
- systemd сохраняет допустимые динамические runtime-зависимости.
  Обновление собственного OpenSSL или Debian libkmod требует пересборки.
- Широкий набор системных интеграций увеличивает число зависимостей;
  изменения профиля требуют внимания к PAM/NSS/resolver и загрузочным
  компонентам.

## Рассмотренные альтернативы
- **Монолитный Debian-пакет.** Проще в сопровождении, но принуждает
  устанавливать неиспользуемые службы и вспомогательные компоненты.
- **Единый пакет `systemd-container` для контейнерных возможностей.**
  Не позволяет независимо выбирать функции управления контейнерами,
  машинами, образами и переносимыми службами.
- **Отдельная сборка systemd на каждый Debian-пакет.** Не выбрана:
  функциональное разделение выполняется на уровне артефактов единой
  сборки, а не отдельных конфигураций исходников.
- **Полностью статический systemd.** Не соответствует потребности в
  динамических системных интерфейсах.
