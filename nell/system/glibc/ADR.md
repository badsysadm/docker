# ADR: профиль сборки glibc

## Статус
Принято.

## Контекст
glibc предоставляет динамический загрузчик и базовые библиотеки, от которых
зависит остальная система NELL. При разбиении glibc на отдельные Debian-пакеты
автоматическое определение зависимостей через `${shlibs:Depends}` может
подставить зависимости на системные пакеты Debian (например, `libc6`),
вместо пакетов `glibc-*` из данного профиля.

## Решение
- Собирать glibc из соответствующей upstream release-ветки.
- Устанавливать в `/usr` через staging root.
- Генерировать только локали `en_US.UTF-8` и `ru_RU.UTF-8`.
- glibc является runtime libc для остальных проектов `nell`; общее правило
  статической линковки зависимостей к самой glibc не применяется.
- Не использовать `${shlibs:Depends}` в пакетах glibc. Зависимости между
  пакетами профиля явно задаются в `debian/control` по фактическим
  зависимостям ELF (`DT_NEEDED`) и назначению компонентов.
- Отключить `dh_makeshlibs` и `dh_shlibdeps` для Debian-упаковки glibc:
  стандартные автоматические метаданные shlibs и разрешение зависимостей
  рассчитаны на пакетную структуру Debian и могут указывать на его `libc6`,
  а не на собственные разделённые пакеты NELL.

## Последствия
- Зависимости пакетов glibc не подменяются автоматически зависимостями
  на системные пакеты Debian.
- При изменении состава или динамической линковки glibc зависимости
  в `debian/control` необходимо актуализировать вручную.
- Пакеты glibc не создают shlibs-метаданные через `dh_makeshlibs`, поэтому
  потребителям этих библиотек не предоставляется автоматическое сопоставление
  ELF SONAME с пакетами NELL. Эти зависимости требуют отдельного учёта.
- В образе доступны только явно сгенерированные локали.
- Совместимость остальных проектов зависит от ABI этой версии glibc.
- Обновление glibc требует проверки всех runtime-зависимых сборок.

## Рассмотренные альтернативы
- Автоматическое формирование зависимостей через `${shlibs:Depends}` —
  не выбрано, поскольку оно ориентируется на доступные Debian
  shlibs/symbols-метаданные и не гарантирует зависимости на
  собственные пакеты NELL.
- Генерация shlibs-метаданных через `dh_makeshlibs` — не выбрана, поскольку
  обычные правила автогенерации не отражают намеренно нестандартную
  схему разделения и замещения Debian libc в NELL.
