# ADR: Профиль Suricata

## Контекст

Suricata сочетает C и Rust, поддерживает несколько механизмов получения
пакетов и использует внешние базы данных для анализа трафика и файлов.
Для профиля необходимо определить набор включённых механизмов и
способ подготовки Rust-зависимостей.

## Решение

- Включить AF_PACKET, NFQUEUE для inline IPS, NFLOG и eBPF,
  включая сборку eBPF-программ.
- Включить GeoIP2 через libmaxminddb и определение типов файлов
  через libmagic.
- Не включать AF_XDP, DPDK и PF_RING.
- Отключить `-march=native`, чтобы не привязывать бинарный файл
  к процессору сборочного хоста.
- Для генерации Autotools-файлов вызывать `autoreconf` вместо
  `autogen.sh`: последний удаляет `rust/Cargo.lock`.
- Использовать статическую libelf из профиля elfutils NELL вместо Debian-архива, не содержащего необходимые внутренние символы elfutils.
- Разделять функции и данные C-кода на отдельные секции и удалять недостижимые секции при линковке, чтобы ограничить объём встроенного кода статических зависимостей.

## Последствия

- Поддержка NFQUEUE позволяет использовать Suricata в inline-режиме.
- Работа eBPF зависит от возможностей ядра и привилегий процесса.
- GeoIP2 требует внешней базы MaxMind DB, а libmagic — базы сигнатур.
- AF_XDP, DPDK и PF_RING недоступны в данном профиле.
- Отключение `-march=native` сохраняет переносимость между
  процессорами x86_64 ценой возможной потери части оптимизаций.
- Удаление секций уменьшает объём неиспользуемого кода, но не гарантирует исключение транзитивных зависимостей: результат зависит от того, как скомпилированы их объектные файлы и какие секции остаются достижимыми.
