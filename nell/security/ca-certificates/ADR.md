# ADR: управляемое хранилище доверенных CA

## Статус
Принято для проверки сборкой.

## Контекст
Готовый trust store необходим уже в образе, но администратор должен
сохранять возможность менять доверие к отдельным CA после установки.

## Решение
- Использовать набор корневых сертификатов из официальных исходников Debian ca-certificates на основе Mozilla.
- Формировать bundle и хешированные ссылки вызовом `update-ca-certificates --fresh` на этапе сборки.
- Сохранять исходные сертификаты, `ca-certificates.conf`, каталог локальных сертификатов и штатную утилиту `update-ca-certificates`.
- Системные CA отключаются через строки с `!` в `/etc/ca-certificates.conf`; локальные CA добавляются в `/usr/local/share/ca-certificates` и удаляются из него.
- Для применения изменений администратор повторно выполняет `update-ca-certificates --fresh`; при сборке не требуется вмешательство пользователя.

## Последствия
- Поставляемый образ сразу содержит `/etc/ssl/certs/ca-certificates.crt` и сертификаты для OpenSSL.
- Для последующей локальной регенерации доверенного хранилища требуется доступный в установленной системе OpenSSL и штатные системные утилиты.
- Локальные сертификаты должны иметь расширение `.crt` и содержать по одному сертификату PEM на файл.

## Альтернативы
- Хранить только объединённый PEM: отклонено, так как исключает штатное управление доверием к отдельным CA.
