# ADR: профиль сборки Vault

## Статус
Принято для проверки сборкой.

## Решение
- Собирать полноценный сервер Vault со встроенным Web UI, без минимального профиля функциональности.
- Собирать UI из upstream-исходников и включать его в серверный бинарник через штатный Go build tag `ui`.
- Подготавливать Go, Node.js, pnpm и все зависимости исключительно в `02_dep.Dockerfile`.
- Загружать Go-модули и формировать `vendor`, а зависимости UI устанавливать до этапа компиляции.
- `03_bin.Dockerfile` должен собирать UI и сервер без сетевого доступа к реестрам зависимостей.
- Использовать `CGO_ENABLED=0`, исключая динамические сторонние зависимости из серверного бинарника.
- Размещать в конечном `scratch`-bundle только серверный бинарник со встроенным интерфейсом.
- Не собирать и не запускать тесты; не включать документацию в конечный bundle.

## Последствия
- Для сборки UI необходимы отдельные инструментальные зависимости, но они отсутствуют в конечном bundle.
- Изменение upstream-зависимостей требует пересборки `dep`-образа, а не загрузки пакетов при компиляции.
- Режимы Vault, требующие CGO, недоступны в таком профиле сборки.
- Для запуска Web UI его необходимо разрешить в runtime-конфигурации Vault.
