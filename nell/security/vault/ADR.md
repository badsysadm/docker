# ADR: профиль сборки Vault

## Статус
Принято для проверки сборкой.

## Решение
- Собирать HashiCorp Vault версии 2.2.1 из официального тега `v2.2.1`.
- Сохранять полноценный сервер и встроенный Web UI (Ember); использовать build tags `vault ui`, не включать `minimal`.
- Собирать UI из исходников штатным `pnpm run build` на Node.js 24.19.0 с pnpm 10.22.0, закреплёнными upstream.
- Собирать Go-бинарник компилятором Go 1.27.3, закреплённым upstream, вместо версии из Debian.
- Использовать `CGO_ENABLED=0`: конечный бинарник не требует сторонних shared-библиотек или libc.
- Сохранять только `/usr/bin/vault` в bundle; интерфейс встраивается через `go:embed`.
- Не запускать тесты и не включать документацию в bundle.
- Для повторяемости сборки применять `-trimpath`, `-buildvcs=false` и пустой Go build ID.

## Последствия
- UI доступен при включении `ui = true` в конфигурации Vault или через `VAULT_UI`.
- Для сборки нужны доступ к upstream Go modules, npm/pnpm и официальному Go toolchain, а также отдельный Node.js build image.
- Статическая компоновка обеспечивается отключением CGO, что исключает режимы интеграции Vault, требующие CGO.
- Полная проверка воспроизводимости выполняется штатным `make vault` с двумя сборками и сравнением SHA-256.
