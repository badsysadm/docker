# ADR: профиль сборки OTS

## Статус
Принято для проверки сборкой.

## Решение
- Получать исходники OTS из официального Git-тега выбранной версии.
- Собирать штатный сервер OTS с Web UI, компилируемым из upstream-исходников и встраиваемым в Go-бинарник посредством `go:embed`.
- Подготавливать Go, Node.js, pnpm, Go vendor и все зависимости frontend в `02_dep.Dockerfile`.
- На этапе `03_bin.Dockerfile` генерировать страницу API и frontend штатными инструментами upstream, затем компилировать сервер без сетевого доступа к Go proxy и npm registry.
- Использовать `CGO_ENABLED=0`, `-mod=vendor`, `-buildvcs=false`, `-trimpath` и заданную upstream переменную `SOURCE_DATE_EPOCH` для воспроизводимой сборки.
- Не собирать и не запускать тесты; документацию не включать в итоговый образ как отдельные файлы. Генерируемая страница API встраивается в Web UI.
- Финальный `scratch`-образ содержит только `/target/usr/bin/ots` с правами `0755`.

## Последствия
- Встроенный Web UI не требует отдельных статических файлов при запуске.
- Для обновления исходников могут потребоваться соответствующие версии Go, Node.js и pnpm.
- Генерация страницы API является частью upstream-процесса сборки frontend.
- Воспроизводимость проверяется штатной командой `make ots`.
