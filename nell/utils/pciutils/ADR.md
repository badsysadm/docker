# ADR: профиль сборки pciutils

## Статус
Принято для проверки сборкой.

## Контекст
Утилитам PCI требуется локальная база идентификаторов устройств
и доступ к конфигурационному пространству PCI через Linux.

## Решение
- Использовать официальный релизный архив pciutils.
- Поставлять `lspci`, `setpci`, `pcilmr` и `update-pciids`
  вместе с базой `pci.ids`.
- Встраивать `libpci` в исполняемые файлы, без общей
  runtime-библиотеки `libpci.so`.
- Оставить поддержку разрешения идентификаторов PCI через DNS.
- Использовать текстовую `pci.ids` без сжатия и не подключать
  необязательные интеграции libkmod и udev HWDB.

## Последствия
- Имена устройств доступны из поставляемой базы `pci.ids`
  даже без сети; `lspci -q` может использовать DNS.
- Сведения из udev HWDB и libkmod не используются.
- `update-pciids` требует доступного в целевой ОС
  загрузчика HTTP(S) и прав на обновление базы.
- `pcilmr` и `setpci` требуют соответствующего доступа
  к оборудованию; для диагностики доступен `lspci`.

## Альтернативы
- Включить libkmod и udev HWDB: не выбрано из-за дополнительных
  runtime-зависимостей.
- Хранить сжатую базу: не выбрано для отказа от зависимости от zlib.
