# ADR: профиль сборки rss2email

## Статус
Принято для проверки сборкой.

## Контекст
rss2email 3.14 — Python CLI для доставки RSS/Atom-публикаций по электронной
почте. Референс упаковки Python runtime в nell — `www/radicale`.
В upstream-теге `v3.14` файл `pyproject.toml` содержит устаревшую версию
`3.12.2` и backend Poetry; официальный `setup.py` получает корректную
версию `3.14` из `rss2email/__init__.py`.

## Решение
- Получать исходники из официального тега `v3.14` репозитория
  `rss2email/rss2email`.
- Использовать Python 3.14.7 из `pkg/dev/python3.14`.
- Системные build-зависимости устанавливать посредством `mk-build-deps`.
- На этапе `dep` собирать wheels `feedparser`, `html2text` и их
  транзитивных зависимостей; пакет rss2email собирать через официальный
  `setup.py bdist_wheel`, обходя несовпадающие метаданные Poetry.
- На этапе `bin` устанавливать только локальные wheels, без сети.
- Упаковывать Python, стандартную библиотеку, зависимости и команду
  `/usr/bin/r2e` в `/target`. Команда повторяет upstream `r2e`
  с фиксированным интерпретатором Python 3.14.
- Использовать glibc 2.44, OpenSSL и zlib из существующих образов
  по аналогии с Radicale, а необходимые Python runtime-библиотеки
  допускать динамическими согласно Python-исключению.
- Не включать документацию, тесты, systemd-unit или конфигурацию
  пользовательского SMTP/LMTP.

## Последствия
- Команда `r2e` работает с пользовательскими данными и настройками
  в XDG-каталогах; сервис и таймер запуска не создаются.
- Доставка через SMTP/LMTP не требует внешнего `sendmail`;
  для режима sendmail нужен отдельно установленный почтовый агент.
- Необходимо проверить совместимость upstream 3.14 с Python 3.14.7,
  запуск `r2e --version`, полноту динамических зависимостей и
  воспроизводимость SHA-256 повторных сборок.
