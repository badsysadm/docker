# CVE Connectors

Набор независимых Python-коннекторов для загрузки сведений об уязвимостях, формирования единого индекса соответствий `PURL CVE` и проверки локальной базы решений о применимости и исправлениях при сборке Debian-пакетов.

## Структура проекта

```text
.
├── aliases
├── connectors/
│   ├── bdu/
│   │   ├── import.py
│   │   └── converter.py
│   ├── debian/
│   │   ├── import.py
│   │   └── converter.py
│   ├── kubernetes/
│   │   ├── import.py
│   │   └── converter.py
│   ├── nvd/
│   │   ├── import.py
│   │   └── converter.py
│   └── github.py
├── db/
│   └── <source-package>/
│       ├── <файл_решений_1>
│       └── <файл_решений_2>
├── debian/
│   └── changelog
├── main.py
├── refresh.py
├── verify.py
└── README.md
```

`main.py` — единая точка входа. Коннекторы запускаются отдельными процессами из каталога `connectors/` и не импортируют код друг друга. `github.py` существует отдельно, но пока не зарегистрирован в `main.py` как источник.

## Источники и файлы

| Источник | Загрузчик | Конвертер | Исходный файл | Промежуточный индекс |
|---|---|---|---|---|
| NVD | `connectors/nvd/import.py` | `connectors/nvd/converter.py` | `/tmp/cve/nvd-cve.jsonl` | `/tmp/cve/nvd-purl.txt` |
| Debian Security Tracker | `connectors/debian/import.py` | `connectors/debian/converter.py` | `/tmp/cve/debian-cve.json` | `/tmp/cve/debian-purl.txt` |
| БДУ ФСТЭК | `connectors/bdu/import.py` | `connectors/bdu/converter.py` | `/tmp/cve/fstec-cve.xml` | `/tmp/cve/fstec-purl.txt` |
| Kubernetes Official CVE Feed | `connectors/kubernetes/import.py` | `connectors/kubernetes/converter.py` | `/tmp/cve/kubernetes-cve.json` | `/tmp/cve/kubernetes-purl.txt` |

Общий индекс: **`/tmp/cve/merged-purl.txt`**.

Загрузка (`get`) и конвертация (`convert`) разделены: уже загруженные исходные данные можно преобразовывать повторно, не обращаясь к внешним источникам.

### Особенности источников

- **NVD:** построчная обработка JSONL; сопоставление программного обеспечения по сведениям из NVD; поисковые PURL преимущественно вида `pkg:generic/...`.
- **Debian:** используются исходные пакеты Debian Security Tracker; PURL вида `pkg:deb/debian_<source-package>`. Временные обозначения `TEMP-*` в выходной индекс не включаются.
- **БДУ ФСТЭК:** XML обрабатывается потоково. Если запись содержит CVE, создаются пары с CVE; если CVE отсутствуют, используется идентификатор `BDU:...`. Не нужно дублировать одну запись одновременно под CVE и BDU.
- **Kubernetes:** официальный JSON-фид, включая бюллетени об отдельных компонентах. Конвертер извлекает имя компонента из доступных сведений (в том числе структурированного OSV), не ведёт справочник имён компонентов и не определяет применимость по диапазонам версий. Если имя компонента достоверно не определено, CVE сохраняется под общим `pkg:generic/kubernetes`. Таким образом, отсутствие распознанного компонента не приводит к потере CVE; однако общий PURL не утверждает, что уязвимость затрагивает все компоненты.

Конвертеры применяют соответствия из корневого `aliases` при формировании промежуточных индексов.

## Команды

Команды запускаются из корня репозитория:

```bash
python3 main.py get [nvd|debian|bdu|kubernetes]
python3 main.py convert [nvd|debian|bdu|kubernetes]
python3 main.py merge
python3 main.py refresh
python3 main.py verify
```

Квадратные скобки здесь обозначают необязательный аргумент; вводить их буквально не нужно.

| Команда | Назначение |
|---|---|
| `get` | Скачать исходные данные всех зарегистрированных источников. |
| `get <источник>` | Скачать данные только указанного источника. |
| `convert` | Пересоздать все промежуточные индексы из локальных исходных данных. |
| `convert <источник>` | Пересоздать индекс указанного источника. |
| `merge` | Объединить промежуточные индексы, отсортировать и удалить идентичные строки. |
| `refresh` | Повторно применить текущие алиасы к уже существующему объединённому индексу. |
| `verify` | Проверить пакет из `debian/changelog` по объединённому индексу и локальным решениям в `db/`. |

### Типовой цикл обновления

```bash
python3 main.py get
python3 main.py convert
python3 main.py merge
python3 main.py verify
```

Если исходные данные уже скачаны, достаточно `convert → merge → verify`. После изменения файла `aliases` можно:

- заново выполнить `convert → merge`, чтобы обновить промежуточные и объединённый индексы;
- выполнить `refresh`, чтобы обновить **только** существующий `merged-purl.txt` без повторной конвертации.

**Важно:** `merge` не читает `aliases`. Если выполнить `refresh`, а позднее `merge` со старыми промежуточными индексами, ранее заменённые PURL могут снова появиться в объединённом файле. Поэтому для полностью воспроизводимой пересборки после изменения алиасов предпочтителен `convert → merge`.

## Формат индекса

Каждая строка содержит ровно одну пару: PURL и идентификатор уязвимости, разделённые пробелом.

```text
pkg:protego/openjdk CVE-2024-12345
pkg:deb/debian_openjdk-11 CVE-2018-3136
pkg:generic/kubernetes CVE-2025-1974
pkg:generic/kubernetes_ingress-nginx CVE-2026-4342
pkg:generic/example BDU:2022-03163
```

Примеры показывают формат записей; не все приведённые сочетания означают подтверждённую запись в текущем индексе.

Индекс не хранит описания CVE, уровни критичности и диапазоны уязвимых версий. Исходные данные источников остаются в соответствующих файлах `/tmp/cve/`.

Один CVE может соответствовать нескольким PURL. При `merge` удаляются **только полные дубликаты строк**: одинаковые PURL и идентификатор. Для сортировки и дедупликации используется системная `sort -u` с `LC_ALL=C`. Итог создаётся во временном файле и заменяется атомарно; промежуточные индексы не изменяются.

## Алиасы PURL

Файл **`aliases` в корне репозитория** задаёт соответствия вариантов названий ПО одному целевому PURL. Первая колонка — каноническое имя для нашего индекса, остальные — его алиасы:

```text
pkg:protego/openjdk pkg:generic/openjdk pkg:generic/oracle/openjdk pkg:generic/redhat/java-17-openjdk pkg:generic/sun_openjdk
pkg:protego/python pkg:generic/python pkg:generic/python_cpython
pkg:protego/openssl pkg:generic/opensslsoftwarefoundation_openssl
```

Например, при конвертации строка

```text
pkg:generic/sun_openjdk CVE-2009-0723
```

должна превратиться в

```text
pkg:protego/openjdk CVE-2009-0723
```

Нормализация приводит имена к нижнему регистру, декодирует процентное кодирование, удаляет пробелы и заменяет неподдерживаемые символы подчёркиванием; при этом и исходный PURL, и записи `aliases` должны нормализоваться одинаково. Поддерживаются цепочки алиасов; конфликты и циклы считаются ошибками. Эти PURL используются как внутренние поисковые ключи и не обязательно совпадают с каноническим форматом Package URL сторонних экосистем.

`pkg:protego/<имя>` — принятый проектом целевой PURL для проверки собственных исходных пакетов. `verify` не должен повторно применять алиасы: он читает уже нормализованный `merged-purl.txt`.

## База решений о применимости и исправлениях

Решения находятся в каталоге **`db/<source-package>/`**. Имя каждого файла произвольное; `verify` объединяет записи всех обычных файлов непосредственно в каталоге (подкаталоги не обходятся). Например:

```text
db/
└── openjdk/
    ├── upstream
    ├── patches
    └── exceptions
```

Формат строки:

```text
CVE-2024-12345 fixed:3.0.16-1 # исправлено начиная с версии
CVE-2024-67890 not-apply # не применяется
BDU:2022-03163 fixed:3.0.15-2
```

Это примеры синтаксиса, а не реальные решения для `openjdk`.

- **`fixed:<версия>`** — минимальная версия исходного Debian-пакета, в которой исправление должно присутствовать. Собираемая версия должна быть **больше или равна** указанной.
- **`not-apply`** — результат триажа: уязвимость к пакету не относится; сравнение версий для такой записи не производится.
- Пустые строки и комментарии `#` допускаются.
- Повтор одного идентификатора в разных файлах (или в одном файле) — ошибка; решения не должны молча перезаписывать друг друга.

Версии сравниваются **через `dpkg --compare-versions`**, а не как строки или числа Python. Это учитывает правила версионирования Debian, включая `epoch`, Debian revision и `~`.

## Проверка пакета: `verify`

`verify.py` извлекает **имя исходного пакета** (`Source`) и **собираемую версию** (`Version`) из `debian/changelog` через `dpkg-parsechangelog`. Для поиска формируется точный ключ:

```text
pkg:protego/<source-package>
```

Алгоритм проверки:

1. Найти все идентификаторы уязвимостей, сопоставленные этому PURL в `/tmp/cve/merged-purl.txt`.
2. Прочитать решения из всех обычных файлов `db/<source-package>/`, если каталог существует.
3. Если в индексе есть CVE/BDU для пакета, каждый идентификатор должен иметь локальное решение; отсутствие каталога решений в этом случае — ошибка.
4. Если для пакета **нет уязвимостей в индексе** и каталога `db/<source-package>/` нет, проверка проходит без требования создать пустую базу.
5. Если каталог решений существует, **все его `fixed:` проверяются независимо от того, присутствует ли соответствующий идентификатор в текущем индексе**. Это предотвращает регрессии относительно уже принятых решений триажа.
6. При ошибках проверка завершается с ненулевым кодом; при успехе — с `0`.

Пример ожидаемой диагностики:

```text
Пакет: openjdk
Версия: 3.0.15-1
PURL: pkg:protego/openjdk
Уязвимостей в индексе: 176
Решений в локальной базе: 1

Проверка не пройдена:
  CVE-2024-12345: отсутствует решение в локальной базе
```

Значения и идентификатор в примере иллюстративны.

**Важный смысл проверки:** `fixed:` является обязательством, зафиксированным локальным триажем. Если CVE впоследствии исчез из текущих внешних баз, собирать версию ниже ранее указанной исправленной всё равно нельзя. `verify` проверяет корректность сравнения версий и наличие решений, но сам не доказывает, что патч действительно включён в исходный код.

## Диагностика

Если `verify` показывает ноль уязвимостей для пакета, который должен присутствовать в индексе, проверяйте результат преобразования и актуальность алиасов:

```bash
# Какие PURL содержат openjdk в объединённом индексе:
awk '$1 ~ /openjdk/ {print $1}' /tmp/cve/merged-purl.txt | sort -u

# Сколько строк сопоставлено с нашим каноническим именем:
grep -c '^pkg:protego/openjdk ' /tmp/cve/merged-purl.txt

# Применить новые алиасы к уже объединённому индексу:
python3 main.py refresh

# Полностью пересобрать индекс с актуальными алиасами:
python3 main.py convert
python3 main.py merge
```

`grep -c` возвращает ненулевой код, если совпадений нет; это не означает ошибку выполнения `verify`. Команда `jq` к файлам `*-purl.txt` неприменима: они содержат обычный текст `PURL CVE`, а не JSON.

## Зависимости

- Python 3 и стандартная библиотека Python для запуска скриптов (если конкретный коннектор не требует дополнительных библиотек).
- `sort` для объединения индексов.
- `dpkg-parsechangelog` и `dpkg` для проверки исходного пакета и сравнения Debian-версий.
- Сетевой доступ к внешним источникам для команды `get`; для `convert`, `merge`, `refresh` и `verify` данные уже должны находиться локально.

Путь `/tmp/cve/` — рабочий каталог данных и индексов; его содержимое не является частью исходного дерева репозитория. При запуске `verify` файл `debian/changelog` ищется относительно текущего рабочего каталога, поэтому проверку следует выполнять из корня собираемого Debian-пакета.
