# dpkg-cvecheck

## Политика сопоставления уязвимостей

При формировании файла `aliases` предпочтительнее включить потенциально лишние соответствия, чем пропустить уязвимость из-за неполного сопоставления названий программного обеспечения. Лишние совпадения допустимы: применимость каждой найденной уязвимости должна быть установлена ручным триажем.

Конвертеры **осознанно не проверяют диапазоны затронутых версий** из внешних баз уязвимостей. Их разбор и интерпретация недостаточно надёжны для автоматического исключения CVE. Проверка применимости к конкретной версии пакета, наличия исправления и обоснование решений `fixed:<версия>` или `not_affected:<justification>` возлагаются на **ручной триаж**.

Подробности работы коннекторов, индекса и проверки: [src/README.md](src/README.md).

## Решения для бинарных пакетов и OpenVEX

Каждый обычный файл `debian/cve/<binary-package>` относится ровно к одному
бинарному пакету, объявленному полем `Package` в `debian/control`.
Одному исходному пакету могут соответствовать несколько отдельных файлов
решений. Формат каждой непустой строки:

```text
CVE-2024-35192 fixed:0.51.2 # Исправление включено upstream начиная с 0.51.2.
CVE-2026-26189 not_affected:component_not_present # trivy-action не входит в бинарный пакет Trivy CLI.
```

Текст после `#` **обязателен** для каждой записи; он без смыслового
преобразования становится полем OpenVEX `status_notes`. Значения
`not_affected:<justification>` ограничены списком OpenVEX:
`component_not_present`, `vulnerable_code_not_present`,
`vulnerable_code_not_in_execute_path`,
`vulnerable_code_cannot_be_controlled_by_adversary` и
`inline_mitigations_already_exist`. Старый `not-apply` недопустим.
`under_investigation` не используется: отсутствие решения блокирует проверку.

`fixed:<версия>` задаётся сопровождающим вручную. `dpkg-cvecheck`
сравнивает указанный порог с полной версией из `debian/changelog` через
`dpkg --compare-versions ... ge ...`; порог может содержать Debian-ревизию,
например `fixed:0.71.0-2`. Утилита не проверяет содержимое исправления:
обоснованность порога устанавливается при ручном триаже.

Статусы `affected` и `under_investigation` не допускаются в решениях:
подтверждённую уязвимость требуется исправить до выпуска, а отсутствие
завершённого триажа блокирует проверку. Генератор не публикует отчёт
о неисправленной уязвимости.

`dpkg-vexgen` формирует **OpenVEX v0.2.0** отдельно для каждого бинарного
пакета в
`debian/tmp/usr/share/vex/<binary-package>.vex.json`. Идентификатор
продукта: `pkg:deb/debian/<binary-package>@<version>` с кодированием
специальных символов версии; версия бинарного пакета по умолчанию равна
`Version` из `debian/changelog` (обычная сборка без binNMU).
В генерации дата записи `debian/changelog` используется как воспроизводимая
временная метка; порядок заявлений и идентификатор документа стабильны.

В результате успешной проверки `fixed` переводится в OpenVEX `fixed`,
`not_affected:...` — в `not_affected` с `justification`, а комментарий
переносится в `status_notes`. Отчёты помещаются в **соответствующие
бинарные** Debian-пакеты через `dh_install`. Отсутствие файла решений
не означает отсутствие уязвимостей и не создаёт пустой VEX.

Полный контракт и этапы разработки:
[src/README.md](src/README.md) и
[план](../../../doc/plans/dpkg-cvecheck.md).

## Использование при сборке Debian-пакета

Команды `dpkg-cvecheck` и `dpkg-vexgen` запускаются **из корня исходного
Debian-пакета**, содержащего `debian/control`, `debian/changelog` и
`debian/cve/<binary-package>`. Для проверки требуется установленный индекс
`/var/lib/cve/db.txt`:

```sh
dpkg-cvecheck
dpkg-vexgen
```

Вторая команда самостоятельно вызывает первую; при ошибке проверки
VEX-документы не публикуются и генератор возвращает ненулевой код.
После успешного запуска документы находятся в
`debian/tmp/usr/share/vex/<binary-package>.vex.json`.

В [`nell/security/trivy/04_deb.Dockerfile`](../../security/trivy/04_deb.Dockerfile)
используется опубликованный образ `deb/dev/dpkg-cvecheck:0.1.0`: из него
устанавливается Debian-пакет инструмента, затем после `dh_prep` и
размещения бинарника вызывается `dpkg-vexgen`, **до** `dh_install`.
Соответствующий [`trivy.install`](../../security/trivy/debian/trivy.install)
включает `usr/bin/trivy` и `usr/share/vex/trivy.vex.json` в бинарный пакет.

Пример запуска стадии из корня репозитория:

```sh
make nell/security/trivy/04_deb.Dockerfile version=0.76.2
```

Отчёт устанавливается по пути `/usr/share/vex/trivy.vex.json`. Trivy не
загружает этот файл автоматически: для его использования необходимо явно
передать `--vex /usr/share/vex/trivy.vex.json`. Нормализация внутренних
`pkg:protego/...` и продуктовых PURL OpenVEX запланирована отдельно в
[`docs/TODO.md`](../../../docs/TODO.md) и в этой интеграции не изменяется.
