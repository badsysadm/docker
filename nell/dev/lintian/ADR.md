# ADR: Lintian с PAR::Packer

## Статус
Принято.

## Контекст
Lintian загружает проверки и некоторые Perl-модули динамически. Кроме того, для выполнения ему нужны собственные базы правил и профили. Автоматическое обнаружение зависимостей `PAR::Packer` не включает все эти компоненты.

## Решение
- Основной исполняемый файл упаковывается через `pp -B`. Модули `lib/Lintian/*.pm` добавляются явно через `-M`; отдельно перечисляются динамически загружаемые Perl-модули, в частности семейство `Data::DPath`, сериализатор `MLDBM` и `_charnames`.
- Встроенные экраны (`Lintian::Screen::*`) загружаются как Perl-модули из PAR; поиск файлов экранов в дополнительных каталогах профиля сохраняется.
- Для `MLDBM` предусмотрен загрузчик `BerkeleyDB/Btree.pm`: класс `BerkeleyDB::Btree` реализован в `BerkeleyDB.pm`, но `MLDBM` загружает его по имени файла.
- В PAR включается `unicore/Name.pl`, необходимый для работы `_charnames`; сторонние разделяемые библиотеки, от которых зависят XS-модули, включаются через `pp -l`.
- Используется Perl-модуль `Debian::DistroInfo` из версионированного upstream `distro-info`, поскольку версия в Debian Trixie не предоставляет требуемый Lintian интерфейс.
- Версия Lintian подставляется в точку входа при сборке. Для PAR-окружения `LINTIAN_BASE` и `THISDIR` указывают на `/usr/share/lintian`.
- В конечном артефакте каталог `/usr/share/lintian` содержит только собственные ресурсы проекта: `data`, `tags`, `profiles`, `vendors`, `private`, `commands`. Каталог `lib` отдельно не устанавливается: Perl-модули находятся внутри PAR.
- Данные `distro-info-data` и `iso-codes` не копируются в артефакт Lintian и предоставляются пакетами, указанными в `Depends`.
- Для воспроизводимой упаковки PAR используются фиксированное время и настройки хеширования Perl.

## Ограничения
- `private/` и `commands/` содержат вспомогательные исполняемые компоненты. Их запуск в отдельных процессах и доступность необходимых модулей из PAR требуют отдельного подтверждения.
