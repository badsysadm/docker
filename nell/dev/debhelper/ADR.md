# ADR: Комплект debhelper через PAR::Packer

## Статус
Принято для проверки сборкой.

## Контекст
`debhelper` — набор команд `dh` и `dh_*`, модулей
`Debian::Debhelper::*` и файлов `autoscripts`.
Сборка должна сохранить весь набор, а не один `dh`.

## Решение
- Использовать официальный архив Debian debhelper 14.5.
- `make version` генерирует `Dh_Version.pm`, `make install`
  устанавливает команды, модули и autoscripts без тестов и документации.
- Для каждой команды `dh` и `dh_*` использовать `pp -B -I lib`.
- Явно включать все локальные `Debian::Debhelper::*` модули через
  `-M`, включая динамически загружаемые реализации последовательностей
  и сборочных систем.
- Установить `autoscripts` в `/usr/share/debhelper/autoscripts`.
- Использовать фиксированное время через `faketime` и фиксированные
  настройки хеширования Perl для воспроизводимой упаковки.
- Не собирать тесты и документацию.

## Ограничения
- `dh` запускает внешние команды из окружения сборки: `dpkg`,
  `make`, `cmake`, `strip`, `file`, `dwz`, `dh-autoreconf` и
  другие по ситуации. Они не включаются в PAR-архивы.
- Внешние `dh-sequence-*` расширения и сторонние buildsystem-плагины
  могут требовать отдельной поддержки: `pp` упаковывает встроенные модули.
- Необходимо проверить сценарий `dh binary --no-act` и реальную сборку
  пакета, особенно обращение к `autoscripts`.
- Проверка `ldd` исполняемого файла не покрывает извлекаемые
  PAR XS-модули; следует проверить сторонние динамические зависимости.
- Воспроизводимость SHA-256 и учет встроенных Perl-компонентов в
  `Static-Built-Using` ещё не подтверждены.
