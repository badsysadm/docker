# ADR: Полный набор исполняемых инструментов devscripts

## Статус
Принято для проверки сборкой.

## Контекст
Для сборки и анализа Debian-пакетов нужен полный набор исполняемых
команд devscripts, а не выборка отдельных программ.

## Решение
- Источник — официальный архив Debian devscripts 2.26.13.
- Все `scripts/*.pl` упаковываются индивидуально с `pp -B -I lib`;
  имена файлов назначения соответствуют именам upstream без `.pl`.
- Явно включены `Dpkg::Changelog::Parse`,
  `Dpkg::Vendor::Default` и `Dpkg::Vendor::Debian`, поскольку
  динамическая загрузка модулей не всегда обнаруживается `pp`.
- Все `scripts/*.sh` устанавливаются как оригинальные shell-скрипты,
  без перевода в Perl/ELF.
- Python-команды устанавливаются без изменения интерпретатора; также
  поставляются `scripts/devscripts/*.py` с файлом версии пакета.
- `debpkg` упаковывается из Perl в служебный путь, а штатный C launcher
  компилируется в `/usr/bin/debpkg`.
- `run_bisect` и `run_bisect_qemu` помещаются в служебный каталог,
  используемый `debbisect`.
- Сохраняются `templates` и `conf.default`, необходимые программам.
- `scripts/setup.py` является установочным скриптом и не включается
  как пользовательская команда.
- `deb-check-file-conflicts` отсутствует в версии 2.26.13 и не включается.
- Тесты и документация не собираются и не поставляются.

## Ограничения
- Perl-архивы `pp` могут потребовать дополнительные явно включённые
  модули при динамических загрузках, особенно в `salsa` и `uscan`.
- Shell и Python-команды требуют соответствующие интерпретаторы;
  Python-инструменты зависят от внешних модулей (например, `magic`,
  `debian`, `requests`) и не являются автономными ELF.
- Большинство инструментов вызывают внешние команды и другие пакеты
  Debian; их наличие в вызывающем окружении требуется отдельно.
- `debpkg` предполагает особую модель прав доступа. Права setuid
  здесь намеренно не устанавливаются; соответствующий сценарий
  требует проверки в целевом окружении.
- Для каждой Perl-программы требуется проверить сценарии запуска,
  включая модули `Devscripts::*` и другие динамические зависимости.
- `ldd` основного файла не обнаруживает зависимости распакованных
  PAR XS-модулей.
- Необходимо подтвердить воспроизводимость SHA-256 и корректность
  `Static-Built-Using` по реально включённым компонентам.
