# ADR: Git с повторным использованием библиотек nell

## Статус
Принято для проверки сборкой.

## Контекст
Git должен предоставлять обычную функциональность, включая HTTPS.
В проекте уже собираются curl, OpenSSL, zlib и Zstandard;
дублировать их компиляцию и зависимости системными вариантами
при сборке Git не требуется.

## Решение
- Использовать библиотеки curl, OpenSSL, zlib и Zstandard из готовых
  OCI-образов nell, сохранив HTTP(S)-транспорт Git.
- Использовать OpenSSL из профиля nell непосредственно в криптографических
  операциях Git, а также в составе зависимостей libcurl; не отключать
  интеграцию Git с OpenSSL через `NO_OPENSSL`.
- Для статических зависимостей curl также использовать libssh2
  и nghttp2 из существующей сборки curl.
- При установке Git использовать его штатные опции
  `INSTALL_SYMLINKS` и `NO_INSTALL_HARDLINKS`, чтобы избегать hardlink
  и дублирования исполняемых файлов.
- Не включать необязательные Rust, Perl, Python, GUI, локализации,
  gitweb и WebDAV HTTP push, как было определено в исходной конфигурации профиля.
- Не устанавливать отдельные исполняемые файлы для встроенных команд Git
  при сохранении необходимых серверных команд.

## Последствия
- HTTPS использует уже собранный стек библиотек nell.
- Отдельные команды Git могут иметь существенный размер из-за
  статической линковки: этот размер необходимо оценить после сборки.
- Возможности, требующие отключённых компонентов, недоступны.

## Альтернативы
- Использовать системные development-пакеты curl и криптографического
  стека: не выбрано из-за дублирования существующих профилей nell.
