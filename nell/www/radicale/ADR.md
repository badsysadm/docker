# ADR: профиль сборки Radicale

## Статус
Принято для проверки сборкой.

## Контекст
Radicale 3.9.0 — Python-приложение. Его зависимости поставляются в wheel-пакетах; часть модулей Python и самого интерпретатора использует динамические библиотеки. Требование статической линковки, применяемое к нативным приложениям в `nell`, не может быть механически применено к Python runtime. Аналог упаковки Python — `buildbot/Dockerfile`.

## Решение
- Получать официальные исходники Radicale из тега `3.9.0`.
- Использовать Python 3.14.7 из имеющегося образа `pkg/dev/python3.14`.
- Собирать wheel-пакет Radicale вместе с зависимостями на этапе `dep`, включая дополнительную зависимость `ldap3` для LDAP-аутентификации.
- На этапе `bin` устанавливать зависимости только из подготовленных wheel-пакетов, без сетевого доступа.
- Укладывать Python, Radicale, Web UI и Python-зависимости в `/target`; вызывать сервер через `/usr/bin/radicale`.
- Для Python runtime и его нативных модулей допустить динамическую линковку как проектное исключение; не изменять общий контракт `nell`.
- Не добавлять конфигурацию развёртывания, systemd-unit и запуск тестов.

## Последствия
- Для выполнения приложения необходимы совместимые с Python 3.14.7 динамические библиотеки, используемые его runtime-модулями; верификация зависимостей обязательна перед принятием сборки.
- LDAP-аутентификация доступна при соответствующей конфигурации Radicale, но не включается по умолчанию.
- Состав и версии транзитивных wheel-зависимостей необходимо проверять при обновлениях и при проверке повторяемости SHA-256.
- Проверка сборки через `make radicale`, содержимого `/target` и идентичности SHA-256 двух последовательных сборок ещё не выполнена.
