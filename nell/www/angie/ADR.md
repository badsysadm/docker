# ADR: профиль сборки Angie

## Статус
Принято для проверки сборкой.

## Решение
- Использовать корневую сборку `angie/Dockerfile` как референс набора модулей и путей установки.
- Получать Angie, PCRE2, zlib и исходники сторонних модулей из официальных Git-тегов в `01_src.Dockerfile`.
- Подготавливать сборочные зависимости через `mk-build-deps` на этапе `02_dep.Dockerfile`; брать статические архивы и заголовки OpenSSL из собственного образа `bin/security/openssl`.
- На этапе `03_bin.Dockerfile` собирать PCRE2 и zlib совместно с Angie через штатные параметры `--with-pcre`, `--with-zlib`; OpenSSL и GeoIP линковать статически.
- Обеспечить динамическую зависимость только от `libc`, используя `-Wl,-Bstatic` и `-Wl,-Bdynamic`.
- Сохранить HTTP, stream, mail и сторонние модули из корневого референса, не переводить их в динамически загружаемые модули.
- Не собирать и не запускать тесты; удалить документацию из конечного `/target`.
- Хранить `angie.service` в `debian/` без копирования в сборочный или конечный образ.
- Финальный образ `FROM scratch` содержит только необходимые файлы под `/target`.

## Последствия
- Исходные версии библиотек и сторонних модулей должны оставаться совместимыми с версией Angie.
- Сборка GeoIP требует статического архива из build-зависимостей.
- Воспроизводимость проверяется штатной командой `make angie`.
