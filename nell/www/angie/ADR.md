# ADR: профиль сборки Angie

## Статус
Принято для проверки сборкой.

## Решение
- Использовать корневую сборку `angie/Dockerfile` как референс набора модулей и путей установки.
- Получать Angie, PCRE2, OpenSSL, zlib и исходники сторонних модулей из официальных Git-тегов в `01_src.Dockerfile`.
- Подготавливать сборочные зависимости через `mk-build-deps` на этапе `02_dep.Dockerfile`.
- На этапе `03_bin.Dockerfile` собирать PCRE2, OpenSSL и zlib совместно с Angie через штатные параметры `--with-pcre`, `--with-openssl`, `--with-zlib`; GeoIP линковать статически.
- Обеспечить динамическую зависимость только от `libc`, используя `-Wl,-Bstatic` и `-Wl,-Bdynamic`, и проверять `DT_NEEDED` готового бинарника.
- Сохранить HTTP, stream, mail и сторонние модули из корневого референса, не переводить их в динамически загружаемые модули.
- Не собирать и не запускать тесты; удалить документацию из конечного `/target`.
- Положить `angie.service` рядом с Dockerfile проекта и установить его в `/target/usr/lib/systemd/system/` без изменения содержания.
- Финальный образ `FROM scratch` содержит только необходимые файлы под `/target`.

## Последствия
- Исходные версии библиотек и сторонних модулей должны оставаться совместимыми с версией Angie.
- Сборка GeoIP требует статического архива из build-зависимостей.
- Проверка `DT_NEEDED` отклоняет сборку, если появляется динамическая сторонняя библиотека.
- Воспроизводимость проверяется штатной командой `make angie`.
