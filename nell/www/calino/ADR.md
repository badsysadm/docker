# ADR: профиль сборки Calino

## Статус
Принято для проверки сборкой.

## Контекст
Calino — веб-клиент CalDAV/CardDAV на React, TypeScript и Vite.
Официальная сборка формирует статические файлы в каталоге `dist/`.
Для их обслуживания нужен HTTP-сервер, однако сам Calino
не требует серверного JavaScript runtime. Зависимости JavaScript
фиксируются в `pnpm-lock.yaml`.

## Решение
- Получать исходники из официального тега, выбранного в профиле сборки.
- Использовать Node.js и pnpm только на этапах подготовки и сборки.
- Устанавливать build-зависимости на этапе `dep` через `mk-build-deps`,
  а JavaScript-зависимости — через `pnpm install --frozen-lockfile`.
- На этапе `bin` запускать `pnpm exec vite build`, без запуска
  тестов и дополнительных проверок типов.
- Не вызывать `scripts/update-sample-events.mjs`: скрипт меняет даты
  демонстрационных событий по текущему месяцу и нарушает
  воспроизводимость сборки.
- Помещать только содержимое `dist/` в `/target/usr/share/calino/`.
- Не включать runtime Node.js, веб-сервер или конфигурацию веб-сервера
  в конечный образ. Статические ресурсы обслуживаются отдельно.
- Применять патч, удаляющий из `index.html` метаданные сайта,
  привязанные к upstream-адресу.
- Применять патч runtime-конфигурации: до инициализации приложения
  загружать `/config.json` с `cache: 'no-store'`. При отсутствии файла,
  ошибке запроса или некорректных значениях сохранять значения по умолчанию.
- Помещать `config.json` в `/target/usr/share/calino/config.json`.
  Во время работы приложения из него читаются `githubRepo`,
  `contactEmail`, `websiteUrl` и `enableServiceWorker`.
- Сохранять `CALINO_SELF_HOSTED=true` как build-time параметр Vite:
  он определяет значение `__CALINO_SELF_HOSTED__` в собранном приложении
  и не управляется через runtime-конфигурацию.

## Последствия
- Конечный bundle содержит статические веб-ресурсы без исполняемого
  серверного приложения; динамическая линковка к нему неприменима.
- При обслуживании SPA маршруты приложения требуют fallback на
  `index.html` со стороны веб-сервера.
- Для прямых запросов браузера к DAV-серверу необходима
  соответствующая настройка CORS либо проксирование.
- `githubRepo`, `contactEmail`, `websiteUrl` и `enableServiceWorker`
  изменяются заменой `config.json` на веб-сервере без пересборки JavaScript.
  Новый файл читается при следующей загрузке страницы.
- Абсолютный путь `/config.json` предполагает размещение приложения
  в корне сайта; сервер должен отдавать этот файл как JSON, а не
  перенаправлять запрос на SPA `index.html`.
- `CALINO_SELF_HOSTED` остаётся параметром времени сборки;
  его изменение требует пересборки.
- Сборка и повторяемость SHA-256 проверяются по общему контракту `nell`.

## Рассмотренные альтернативы
- Запускать `pnpm build`: отклонено из-за календарно-зависимого
  обновления `sample-events.ics` и дополнительной проверки типов.
