# ADR: Профиль libmnl

## Статус

Принято.

## Контекст

libnetfilter_queue и другие библиотеки Netfilter используют libmnl. Для сборки с независимым от Debian набором статических архивов требуется единый источник этой зависимости.

## Решение

Предоставлять libmnl отдельным профилем NELL, доступным для других библиотек Netfilter. Собирать оба вида библиотеки с PIC и размещать их в стандартном дереве профиля.

Применять hardening при компиляции: `_FORTIFY_SOURCE=3` для проверок операций с памятью, `-fstack-protector-strong` и `-fstack-clash-protection` для защиты стека, `-fcf-protection=full` для защиты потока управления на поддерживаемых x86_64 и `-ftrivial-auto-var-init=zero` для инициализации автоматических переменных. При линковке включать RELRO и немедленное разрешение символов (`-z relro`, `-z now`).

Компилировать функции и данные в отдельные секции (`-ffunction-sections`, `-fdata-sections`) и применять `--gc-sections` при линковке: это даёт потребителям статического архива возможность исключать неиспользуемые секции при соответствующей финальной линковке.

## Последствия

Зависимые профили могут использовать libmnl из OCI-образа NELL. Потребители статической библиотеки должны явно включать её в линковку.

Защитные механизмы не заменяют проверки полученного бинарного файла; эффективность исключения секций зависит от графа ссылок и параметров линковки конечного потребителя. Не все флаги линковщика одинаково влияют на статический архив и разделяемую библиотеку.

## Рассмотренные альтернативы

Оставить libmnl из Debian: это лишает NELL контроля над статически встраиваемой версией библиотеки.
