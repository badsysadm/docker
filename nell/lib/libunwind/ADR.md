# ADR: libunwind 1.8.3

## Статус
Принято для проверки сборкой.

## Контекст
Статический архив libunwind из Debian содержит релокации
`R_X86_64_32S`, несовместимые с линковкой PIE в htop.
Требуется собственный профиль с позиционно-независимым кодом.

## Решение
- Использовать официальный release tarball libunwind 1.8.3.
- Собирать статические (.a) и динамические (.so) библиотеки.
- Компилировать с `-fPIC` и `--with-pic`, чтобы статические
  архивы можно было включать в PIE и shared-объекты.
- Включить ptrace backend для просмотра стека стороннего процесса.
- Отключить сборку тестов и удалить документацию.
- Отключить mini-debuginfo (LZMA-компрессированные таблицы),
  чтобы не вводить отдельную зависимость от liblzma в этот профиль.
- Использовать каталог `/usr/lib/x86_64-linux-gnu` для библиотек;
  в зависимых проектах переносить их в локальный путь компоновки.

## Последствия
- Профиль предоставляет статические и динамические библиотеки,
  включая libunwind и libunwind-ptrace.
- Выключена обработка mini-debuginfo, но ptrace unwinding сохранён.
- PIE при статической линковке архива необходимо проверить сборкой
  зависимого проекта, а не предполагать успешным заранее.
- Две последовательные сборки и состав /target требуют проверки.
