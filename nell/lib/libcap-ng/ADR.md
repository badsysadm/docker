# ADR: libcap-ng — профиль NELL

## Статус

Принято.

## Контекст

Suricata использует libcap-ng; статический архив необходим для отказа от динамической зависимости.

## Решение

Сохранить штатные утилиты Linux capabilities и собрать библиотеку в обоих форматах, без Python bindings. После общей сборки отдельно перелинковать CLI с `libcap-ng.a` через `LDADD`, поскольку стандартное правило Libtool выбирает разделяемую библиотеку и оставляет зависимость CLI от `libcap-ng.so.0`.

Компилировать функции и данные в отдельные секции (`-ffunction-sections`, `-fdata-sections`), позволяя потребителю статического архива исключать неиспользуемые секции при финальной линковке с `--gc-sections`.

## Последствия

Статический архив доступен другим профилям NELL, разделяемая библиотека остаётся в итоговом артефакте.

## Рассмотренные альтернативы

Использование Debian-библиотеки отклонено для Suricata из-за обнаруженной динамической зависимости.
