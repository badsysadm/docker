# ADR: SQLite as a PIC-capable static dependency

## Статус
Принято для проверки сборкой.

## Контекст
Системный статический архив SQLite не гарантирует пригодность для включения в разделяемые модули. util-linux использует SQLite через liblastlog2.

## Решение
Использовать официальный release archive SQLite и собирать статическую и разделяемую библиотеки из одной конфигурации. Объекты компилировать с PIC и разделением функций и данных по секциям, чтобы потребители статического архива могли исключать неиспользуемый код на этапе финальной линковки. util-linux получает статический архив и заголовки из NELL OCI-профиля, а не из Debian. Математические SQL-функции отключены (`--disable-math`), чтобы не включать непозиционно-независимый Debian `libm.a` в разделяемую библиотеку. Библиотеки `.a` и `.so` собираются с PIC; CLI `sqlite3` собирается отдельным вызовом `make` без PIC, с `-no-pie` и статической `libm.a`.

## Последствия
Один набор исходников обеспечивает совместимые библиотечные интерфейсы. Итоговая линковка потребителей должна учитывать их остальные зависимости отдельно. Математические SQL-функции SQLite недоступны в библиотеке и CLI. Для CLI сохраняется встроенная команда `.diskused`, использующая `ceil()` из статической `libm.a`; динамическая зависимость от `libm.so` не требуется.

## Рассмотренные альтернативы
Использование системного Debian-архива отклонено, поскольку требования PIC для его содержимого не подтверждены. Сохранение математических SQL-функций потребовало бы PIC-совместимого `libm.a`; вместо этого принято отключить их.
