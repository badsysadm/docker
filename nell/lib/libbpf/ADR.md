# ADR: libbpf — профиль NELL

## Статус

Принято.

## Контекст

Suricata использует libbpf; статический архив необходим для отказа от динамической зависимости.

## Решение

Для статической и разделяемой сборки libbpf использовать штатный src/Makefile и существующие профили elfutils и zlib.

Выделять функции и данные в самостоятельные секции (`-ffunction-sections`, `-fdata-sections`), чтобы при финальной статической линковке потребитель мог исключить неиспользуемый код с `--gc-sections`. Для разделяемой libbpf явно передавать статические архивы зависимостей в группе линковщика: это разрешает взаимные ссылки между архивами и не добавляет динамические зависимости от libelf, zlib и zstd.

## Последствия

Статический архив доступен другим профилям NELL, разделяемая библиотека остаётся в итоговом артефакте.

## Рассмотренные альтернативы

Использование Debian-библиотеки отклонено для Suricata из-за обнаруженной динамической зависимости.
